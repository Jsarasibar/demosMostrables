ANALISIS DETALLADO - DEMO REPORTE MENSUAL

1) Funcionalidad actual
- Objetivo: consolidar ventas, gastos y clientes en un reporte mensual unico con metricas y visualizaciones.
- Flujo actual:
  1. Lee CSVs de ventas y gastos + Excel de clientes
  2. Convierte fechas
  3. Calcula subtotal, total de venta y metricas principales
  4. Cruza ventas con clientes
  5. Genera tablas agregadas por producto, categoria, canal y cliente
  6. Exporta a output/reporte_mensual.xlsx con formato y graficos
- Valor que ya demuestra bien:
  - Integracion de fuentes distintas.
  - Paso de "datos sueltos" a "reporte ejecutivo".
  - Presentacion visual lista para decision.

2) Que hay que cambiar si o si (obligatorio)
- Robustez frente a datos incompletos:
  - Si falta categoria/canal/cliente en algun registro, algunas vistas pueden quedar inconsistentes.
  - Agregar fillna y validaciones minimas antes de agrupar.
- Control de supuestos de descuento:
  - El script usa (1 - descuento/100), pero en los datos hay descuentos como 0.05.
  - Con ese calculo, 0.05 se interpreta como 0.05% (probable error de negocio).
  - Hay que definir si descuento esta en porcentaje entero (5) o tasa (0.05) y normalizar.
- Consistencia temporal en titulo:
  - El titulo fija "ENERO 2026" de forma hardcodeada.
  - Si se cambian archivos/mes, el titulo quedara mal.
  - Derivar mes/anio desde datos para evitar error en demo.

3) Mejoras recomendadas (sin subir complejidad)
- Hoja de "Control de calidad":
  - Registros sin cliente
  - Registros con montos negativos o nulos
  - Registros con fecha fuera de rango
- KPI adicionales simples:
  - Margen (%) = Ganancia / Total vendido
  - Participacion por canal
- Mejorar narrativa del resumen:
  - Frase automatica con comparacion de top categoria vs segunda.

4) Riesgos de demo y mitigacion
- Riesgo: se vea "muy tecnico".
  - Mitigar mostrando primero problema de negocio (archivos separados, sin visibilidad consolidada).
- Riesgo: dudas sobre exactitud de calculos.
  - Mitigar con hoja de datos procesados + reglas explicadas en 30 segundos.

5) Guion sugerido para mostrar (7-10 min)
- Antes:
  - Mostrar rapidamente los 3 archivos de entrada.
- Automatizacion:
  - Ejecutar script y remarcar que se integra todo en un paso.
- Resultado:
  - Abrir hoja Resumen, luego graficos, luego Clientes.
- Cierre:
  - "Esto no reemplaza ERP/BI completo, pero elimina armado manual mensual".

6) Alcance recomendado (demo simple)
- Mantener:
  - Un mes de datos
  - Graficos basicos
  - Metricas entendibles para duenio/administracion
- Evitar por ahora:
  - Forecasting
  - Modelos predictivos
  - Tableros web en tiempo real

7) Checklist de "demo lista para vender"
- Definicion de descuento cerrada y correcta.
- Titulo del reporte se genera segun periodo real.
- Carga sin errores con datos de ejemplo.
- Graficos visibles y legibles.
- Mensaje de impacto en tiempo/decision claro.

Conclusion
Es la demo mas "lista para mostrar" de las tres porque ya entrega un Excel final completo. Los ajustes obligatorios son de calidad de datos y reglas de negocio (especialmente descuento) para evitar conclusiones equivocadas en una presentacion comercial.

ERRORES/OBSERVACIONES VERIFICADAS (Revision tecnica del 2026-05-28)
- Error de ejecucion real (bloqueante):
  - Al ejecutar `python src/generar_reporte.py` falla con `ModuleNotFoundError: No module named 'pandas'`.
  - Causa: dependencias de `requirements.txt` no instaladas en el entorno actual.
- Error conceptual de negocio (importante):
  - El campo `descuento` en datos usa formato tasa (ej. 0.05, 0.10, 0.12).
  - El calculo aplica `1 - descuento/100`, interpretando 0.05 como 0.05% y no 5%.
  - Impacto: subestima fuertemente descuentos reales y distorsiona metricas (total vendido, ticket promedio, ganancia).
- Riesgo de mantenimiento:
  - Titulo de reporte hardcodeado: "ENERO 2026".
  - Si se reutiliza con otro periodo, puede quedar informacion temporal incorrecta.

CAMBIOS IMPLEMENTADOS (2026-05-28)
1) Error de ejecucion por dependencias

2) Correccion de regla de descuento (error conceptual clave)
- Antes: `total_venta = subtotal * (1 - descuento/100)` (interpretaba 0.05 como 0.05%).
- Ahora: se normaliza el descuento a tasa:
  - Si valor <= 1, se asume tasa (0.05 = 5%).
  - Si valor > 1, se asume porcentaje entero (5 = 5%).
- Impacto: metricas comerciales coherentes y sin subestimar descuentos.

3) Titulo dinamico por periodo
- Antes: titulo hardcodeado "ENERO 2026".
- Ahora: se deriva automaticamente desde fechas de ventas/gastos.

- Se evita que agrupamientos fallen o queden inconsistentes por nulos.

5) Hoja de control de calidad

  - ventas sin fecha valida
